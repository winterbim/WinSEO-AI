### Critère de sortie M2

Le test apps/api/src/autofix-postgres-routes.integration.test.ts exécute le parcours sur le store PostgreSQL avec le client REST WordPress relié à un simulateur en processus. Il couvre la proposition depuis le HTML lu, l’aperçu, l’approbation MFA liée au hash, l’écriture idempotente du patch alt R0 et son reçu, puis live_verified après les quatre observations navigateur/Googlebot × brut/rendu. Pour le titre R1, il couvre la déclaration manuelle, le maintien en attente avant écriture, le recrawl après modification, puis la vérification live. Les deux rollbacks ramènent au hash SEO HTML initial; un autre tenant reçoit 404. packages/db/src/patch-rls.test.ts ajoute les contrôles PostgreSQL de RLS, compare-and-swap et journal append-only. Les tests du domaine couvrent transitions, conflits, valeurs hors politique, idempotence et parité UA. Les statuts de preuve sont consultables depuis l’interface autofix.

Commandes exécutées le 2026-10-06 : pnpm verify — exit 0 (lint, typecheck, tests et builds du workspace); pnpm --filter @serpvera/api demo:autofix — exit 0, hash initial/final identique; pnpm --filter @serpvera/api demo:autofix:e2e — exit 0, 1 test intégré réussi; migration 0014_proven_patch_lifecycle appliquée. Le script E2E démarre Fastify et le simulateur dans le processus de test, applique les migrations et exige PostgreSQL local démarré.

Limites conservées : l’adaptateur REST est exercé contre son simulateur, pas contre un WordPress réel; détection de plugin SEO, cache CDN, preview navigateur avec capture, contrôle d’egress pour une cible CMS configurable, observation Google et mesure avec groupe témoin restent hors M2. La boucle et ses routes d’écriture sont fixture-only/hors production. Cela ne permet pas d’annoncer le produit complet ou un dépassement de tous les concurrents.
